# 企业接入边界

本项目把“企业售后 Agent”做成可运行的教学闭环：客户描述问题，系统查询订单与政策，确认材料，提交申请，等待企业审批，调用模拟退款并按请求编号核对结果。下面区分当前代码已经提供的能力与真实企业还要补上的能力。

## 当前项目已经验证

| 能力 | 当前实现 |
| --- | --- |
| 身份和租户隔离 | 服务端从固定演示账号映射身份；订单、会话、材料、记忆和申请都检查租户与用户 |
| 政策依据 | 默认 BM25，可选 Milvus 混合检索；核对租户、有效版本与内容摘要 |
| 多模态输入 | Replay 支持内置损坏照片；AI 模式可接百炼视觉、ASR 与 TTS |
| 人工参与 | 客户确认申请，审核人员批准、退回或拒绝；退回和拒绝需要理由 |
| 持久化恢复 | PostgreSQL 保存申请、Graph Checkpoint、长期偏好和退款回执 |
| 受控执行 | 退款金额来自申请快照；MCP 和业务层再次检查审批、订单归属、余额与版本 |
| 幂等与故障 | 稳定请求编号、既有回执核对、提交前失败和响应丢失演示 |
| 复杂材料 | 受限 Workspace、Skill、两个 Subagent、逐字引用验收、人工未决项、报告版本绑定及过期提示 |
| 质量验证 | 独立数据库执行 10 项业务回归，可加 5 项真实 AI 任务；保存配置快照、规则/Judge 和 Trace |

## 生产环境还需要接入

1. 将固定账号替换成 OIDC/SSO、岗位授权、停用和退出机制。
2. 将订单、物流和退款 MCP 适配到真实系统，处理渠道异步通知、验签、对账和退款失败。
3. 使用对象存储、备份、迁移、访问审计、脱敏和保留策略管理原始材料。
4. 为长任务增加可靠队列、Worker、租约、取消和状态推送；当前项目适合单机教学运行。
5. 增加账号级限流、并发配额、费用预算、模型降级和供应商故障处理。
6. 使用真实目标模型和真实业务样本做安全、成本、延迟和稳定性评测，并对关键结果人工抽查。
7. 建立指标与告警，至少观察模型错误、工具错误、审批积压、退款待核对、数据库和材料存储状态。

当前代码没有接入真实支付、物流、企业认证或生产监控。课程中的通过结果只说明本地教学链路满足已列出的验收条件。

## 本轮重构验证记录（2026-10-21）

- 类型检查和前后端构建通过。
- 27 项单元测试通过，覆盖申请状态、材料归属、政策重验、报告过期、评测比较、文件工具范围，以及检索适配器和 Embedding/Rerank 的 HTTP 契约。
- 16 项集成测试通过（含嵌套用例）。真实 PostgreSQL、MCP 子进程和 LangGraph 参与执行；每组使用临时数据库。新增用例覆盖材料移除、切换订单、旧草稿确认、历史政策追问、非法回答隔离和五项 AI 任务的报告生成。
- 浏览器检查通过：生产构建启动、客户提交、企业审批、历史记录、连接恢复、移动端，以及评测配置快照与同组样本比较。截图位于 `test-artifacts/usability-*.png`。
- Replay 当前实现为 10/10，故意注入金额展示故障的基线为 9/10；AI 批量链路使用本地协议替身验证 15/15，以及“规则通过但 Judge 异常仍不能通过”的分支。这些数字不是供应商模型的实测质量。

本轮没有调用收费供应商进行效果评测，也没有启动真实 Milvus。混合检索适配器已通过请求、过滤、版本摘要与结果绑定测试；实际服务连通性、召回效果和模型稳定性，应使用 README 的可选配置另行验收。

MCP SDK 已从 1.29.0 更新为同一主版本的 1.32.1。依赖审计仍报告 4 个 high 节点，来自 `deepagents → fast-glob → micromatch → braces` 依赖链的嵌套模式拒绝服务告警。调查入口现仅允许固定目录、明确输入文件与本角色交付文件，拒绝动态 glob/grep 和任意路径；这项入口限制不等于依赖本身已修复。发布到不可信环境前仍需跟踪上游修复，不能直接使用审计建议的破坏性降级。

本轮保留全部九个小节标题和顺序，第一小节正文未改，只同步其余受影响文章的源码说明。没有修改任何 `.env`、`.env.*` 或 `.env.example` 文件。
