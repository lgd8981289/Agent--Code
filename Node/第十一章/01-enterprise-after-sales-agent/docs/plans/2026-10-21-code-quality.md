# 售后项目代码质量调整计划

**目标：** 修复已验证的异常路径，让课程主调用链更容易阅读，并用回归检查约束后续改动。

**方案：** 保留 NestJS、Vue 3、MCP 和持久化工作流。语音输入、播放、会话请求各自拥有状态；服务通过依赖注入装配；列表摘要与详情分开查询。诊断 Trace 写入失败独立报告，业务审计继续保留现有持久化边界。

**技术栈：** TypeScript、NestJS、Vue 3、PostgreSQL、MCP SDK、Zod、node:test、Playwright。

## 执行步骤

1. 修复 `server/mcp.ts` 的失效连接缓存；增加工具输出契约与断线恢复测试。只重建后续调用连接，不自动重放退款操作。
2. 修复 `server/trace.ts` 异常覆盖和 `server/evaluation.service.ts` 清理失败导致的运行状态残留；注入故障验证返回结果与资源释放。
3. 在 `web/src/composables/` 提取语音输入和播放逻辑；两种录音模式统一停止、取消和卸载，覆盖迟到的媒体授权/网络结果。
4. 统一 `ApplicationService`、`CaseService` 的 Repository 和 Knowledge 注入；隔离测试与评测通过同一工厂装配业务服务。
5. Bootstrap 返回身份、能力与小型侧栏参考信息；新建会话摘要列表接口，当前会话详情按需加载。前端提取会话状态、聊天内容和申请面板，按当前页面轮询需要变化的申请，避免全量刷新。
6. 增加测试类型检查、lint 与格式化脚本；补齐前后端回归并运行 check、unit、integration、browser。
7. 更新 README、架构/验证文档以及第十一章相关课程文章，核对所有入口、对象来源和运行描述。

## 验收证据

- 备用录音停止后释放所有音轨；取消后不上传、不覆盖草稿。
- MCP 已连接后断开，下一次查询重新连接；无效工具结果被契约拒绝。
- Trace 故障不覆盖业务结果；评测清理故障后仍能开始新一轮。
- 浏览器聊天、流式响应、材料、审批、朗读、会话切换通过回归。
- 轮询不再下载所有会话消息与评测详情；延迟响应不能覆盖新账户/会话。
- 全部检查真实运行，AI 实测与 Replay/测试替身明确区分，不修改环境配置或用户演示数据。
